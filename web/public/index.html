How it works

  1. Representation. Each frame is a set of 2D Gaussians: position, Cholesky factor of the inverse covariance, and an RGB colour. A pixel is the weighted sum of colours (accumulated blending), as in GaussianImage/GSVC.
  2. Training in the browser. Rendering, analytic gradients and Adam are written in C and compiled to WebAssembly (about 7 KB).
  3. Temporal prediction. Each frame starts from the previous frame's splats, so only a few iterations are needed and only parameter changes are stored.
  4. Add and prune. New splats are added where the error is high (motion or new objects); low-contribution splats are pruned at keyframes.
  5. Keyframe detection. If the error after prediction jumps compared with the last keyframe, the frame is retrained from scratch as a keyframe.
  6. Quantization and entropy coding. Positions are quantized to 12 bits, covariance and colour to 8 bits (per-channel ranges fixed at the keyframe). Predicted frames send only meaningful changes (dead-zone), and everything is deflate-compressed. PSNR is measured after dequantization, exactly as a decoder would see it.

This is a lightweight implementation inspired by GSVC (Wang, Shi & Ooi, arXiv:2501.12060), not a port of the official code. Results are not comparable with the paper, which uses a GPU, full resolution and learned quantization.
